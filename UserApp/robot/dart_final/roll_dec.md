# roll_dec — 旋转解耦飞镖（路线二）· 分支设计文档

<p align='right'>roll_dec 分支 · ai @ dart_final_work</p>

> 本分支 = `dart_final` 的实验版本：**让飞镖自由滚转（自旋），用滚转角 γ 把“空间指令”旋转到弹体坐标系**，
> 使随弹体一起滚的舵面仍能产生正确的空间控制方向。属于“旋转解耦”，**不与 main 合并**（纯实验）。

---

## 1. 什么是“旋转解耦”

“旋转解耦飞镖”不是标准飞镖分类，而是一个**技术目标**：让飞镖绕纵轴的滚转运动**不干扰/不污染**俯仰、偏航的控制 —— 即“转”和“拐弯”互不打架。

来源：南航长空御风 2022 赛季开源提到“既有稳定性又有偏航、滚转和俯仰**解耦控制**的气动设计”。属早期探索概念，非成熟方案。

### 为什么需要
飞镖细长、飞行中易滚转。若俯仰/偏航舵面**随弹体一起滚**，舵面在空间中的偏转方向就会跟着转：
本想“向上拐”，弹体滚了 90°，同样的舵偏就变成“向左拐”。解耦要解决的就是：**不管怎么滚，俯仰/偏航的控制效果稳定、可预期。**

### 与“双层云台的运动学解耦”区别
云台那是**机构层**（外层 Yaw 转，内层补偿角速度）；飞镖的旋转解耦是**气动/控制层**（弹体自己在空中滚，控制律识别并补偿）。

## 2. 两条路线

| | 路线一：机械/伺服解耦 | **路线二：算法解耦（本分支选用）** |
|---|---|---|
| 弹体滚不滚 | 滚 | 滚 |
| 舵面是否随弹体滚 | **不**（机械/伺服隔离，空间指向稳定） | **是**（随弹体一起滚） |
| 改什么 | 机械结构 / 伺服驱动 | **控制算法**（不动机械） |
| 做法 | 陀螺测 γ，伺服反向 -γ 保持舵面空间指向 | 陀螺测 γ，把空间指令旋转到弹体坐标系 |
| 舵机收到的指令 | 已补偿的空间稳定偏转 | 弹体坐标系下的偏转 |
| 对飞镖 | 体积/成本高 | **仅加算法，增量成本低** |

**本分支选路线二**：机械不动，只需“陀螺 + 一段旋转矩阵代码”。

---

## 3. 路线二核心

```
空间指令(制导律给出)  (a_y_space, a_z_space)
        │  R(γ)   γ = 弹体滚转角(IMU 姿态解出)
        ▼
弹体坐标系指令 (δ_pitch_body, δ_yaw_body)
        │
        ▼
      舵机(随弹体滚, 但偏转已补偿)
```

**公式**（旋转矩阵，γ 为绕纵轴滚转角）：
```
δ_yaw_body   =  a_y_space*cosγ + a_z_space*sinγ
δ_pitch_body = -a_y_space*sinγ + a_z_space*cosγ
```
本机目标水平移动、不控高 ⇒ `a_z_space = 0`，于是：
```
δ_yaw_body   = a_y_space*cosγ
δ_pitch_body = -a_y_space*sinγ
```
即：一个“水平”的空间指令，在弹体坐标系里随 γ 在 yaw/pitch 之间分配 —— 舵面随弹体滚，也能持续产生水平方向的控制效果。

## 4. 本分支实现

### 4.1 完整流水线（`app/guidance.c`）
```text
相机(随机体滚) -> 像素(x,y) [体轴]
   │  [输入解旋] R⁻¹(γ):  xs = dxb·cosγ + dyb·sinγ
   ▼
空间视线角 λ = xs/focal  -> dλ(微分+低通, 在空间系算)
   │
   ▼  png_ai
空间横向指令 (ay_space, az_space=0)
   │  [输出旋转+相位超前] R(γ_eff), γ_eff = γ + ω·τ_lead
   ▼
体轴 (yaw_body, pitch_body) -> servo_mix_ai -> 4 舵机
```
> **注意**：输入解旋与输出旋转互为逆；中间必须在“空间系”里微分/滤波，否则 `dλ` 会混入伪速率 `γ̇·λ`。

### 4.2 关键 cfg（`dart_final_cfg.h`）
- `GUID_ROLL_DEC_ENABLE`（1=启用；0=传统稳滚）
- `GUID_ROLL_SIGN` / `GUID_ROLL_OFFSET_DEG`（γ 符号 / 零点偏置）
- `GUID_DEROT_IN_ENABLE` / `GUID_IN_ROT_SIGN`（**输入侧解旋**，默认开）
- `GUID_LEAD_MS`（**相位超前**，补偿舵机滞后）

### 4.3 为什么“不止一行”
| 必需项 | 说明 |
|---|---|
| 输入解旋 | 相机随机体滚，像素是体轴坐标；不解旋则方向错、dλ 混入 γ̇·λ |
| 输出旋转 | 核心 2×2 旋转（简单） |
| 相位超前 | 舵机滞后 τ → 用 γ+ω·τ 补偿，否则系统偏 ωτ |
| 陀螺 | 量程/带宽/连续性/零偏温漂 + 起飞前静止校准 |
| 残余耦合 | 马格努斯/陀螺交叉，旋转矩阵**消不掉**（需 ADRC/补偿项） |
| 带宽匹配 | 自旋速度必须 < 舵机有效带宽（50Hz PWM ≈ 几 Hz） |
| 配平/符号 | 零位与符号错 → 锥形运动；须地面标定 |

- 滚转角来源：`imu` app 发布的 `attitude.roll_deg`（BMI088 + 姿态解算）；角速率用 `attitude.gx_dps`。
- 关闭 `GUID_ROLL_DEC_ENABLE` 时退回传统“仅控 yaw + roll PID”。

## 5. 关键坑（务必注意）

1. **陀螺零漂 → γ 缓慢漂移**：飞行前静止校准零偏；飞行时间短（几秒）可接受；必要时 LPF/融合。
2. **滚转快 → 舵机带宽不足**：补偿滞后。选快舵机 / 限制自旋速度 / 前馈。
3. **坐标系/符号统一**：γ、空间指令、舵面偏转方向必须同一套定义（x 纵轴, y 右, z 上）。**符号错则越补越歪** → 地面转弹体验证 `GUID_ROLL_SIGN`。
4. **残余气动耦合**：本分支只补偿“控制坐标系错位”；马格努斯/陀螺效应等气动耦合若仍大，需再加补偿（可参考 smc/adrc 分支）。
5. **BMI088 够用**：低速飞镖短时飞行，BMI088 绰绰有余；门槛在**起飞前静止校准 + 简单滤波**，而非芯片。

---

## 6. 低速（~20m/s）补充

- 舵效 `K ∝ V²`：20m/s 的舵效仅是 30m/s 的约 44%，**别指望大舵偏硬掰**；尽早开始制导、慢慢修正。
- 低速下马格努斯/陀螺效应**变弱**，路线二要补偿的主要是“坐标系错位”，算法更干净。
- 气动外形/重心仍需重视（尾翼优先、重心靠前），但**不在本分支范围内**。

---

## 7. 验证步骤（建议）

1. 地面转弹体，确认 `attitude.roll_deg(γ)` 跟得上；
2. 给定固定 `a_cmd` 与人为 γ，验证体轴 yaw/pitch 输出符合公式；
3. 校准零偏+滤波，静置看 γ 漂移；
4. 地面舵机测试：转弹体看舵面是否随 γ 正确分配；
5. 飞行对比：旋转解耦 vs 固定 k（main 分支）的命中效果。
